# Information Refinement Lab

A date in a planning system, a customer schedule and a meeting note can all refer to the same delivery while making different claims. This lab shows how to connect selected information, preserve those meanings and prepare a briefing that another person can check.

<!-- interactive: information-refinement -->

## Read further

- [W3C Data on the Web Best Practices](https://www.w3.org/TR/dwbp/): read the sections on metadata, provenance and data quality for ways to make reused information understandable and assessable. These principles inform the source cards; they do not certify the fictional data.
- [W3C PROV Primer](https://www.w3.org/TR/prov-primer/): its distinction between entities, activities and responsible agents helps explain which source supported a result, which process derived it and who was involved. This small lab uses explicit fields and rules; it does not require RDF or a graph database.
- [Write the Docs: Docs as Code](https://www.writethedocs.org/guide/docs-as-code/): see how versioning, review and automated checks support maintained information. The same workflow can govern the excerpts and rules used here.
