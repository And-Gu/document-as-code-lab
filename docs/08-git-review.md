# Git, Review, and Collaboration


## Learning Goal

Treat documentation changes as reviewable work.

## Planned Topics

- Commits, branches, and pull requests
- Reviewing text, diagrams, and data
- Approval scope: an information item, a collection, or an assembled publication
- Recording who reviewed which source version; why a commit or status field alone is not approval evidence
- Deciding when later changes require renewed review
- Finding affected outputs when a shared procedure changes
- Issues and decisions
- Release boundaries and publication checks for consistency, completeness, and presentation

## Planned Exercise

Use a working copy of chapter 1's onboarding example to propose a change to the access procedure. Identify the handbook and training excerpt that reuse it. Record the review decision, reviewer, and exact source version, then explain which checks are still needed before releasing the assembled handbook. Keep this practice record separate from the fixed showcase's fictional statuses.

Expected result: a review record with an explicit scope and a list of affected outputs. A later source edit must be distinguishable from the version that was reviewed.

## Completion Criteria

The chapter explains the planned topics, includes a reproducible exercise, and documents relevant limitations. Product-specific behavior must be verified when the chapter is drafted.
